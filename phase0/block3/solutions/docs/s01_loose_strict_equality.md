# S1 解説: `==` と `===` の違い

## このStepのポイント

PHP の `==` と `===` の挙動を、5つの「直感に反するケース」で確認した。

## なぜ `==` は危険なのか

PHP の `==` は、比較の前に **型変換(型ジャグリング)** を行う。
このため、人間が「異なるはず」と感じる値が「等しい」と判定される。

| 比較 | 結果 | 理由 |
|------|------|------|
| `"0" == false` | true | "0" は偽とみなされる文字列 |
| `null == false` | true | null も false も偽値 |
| `[] == false` | true | 空配列も偽値 |
| `"10" == 10` | true | 文字列が数値に変換される |

## PHP 8 で変わった点

PHP 7 まで、`"abc" == 0` は **true** だった。
これは「数字ではない文字列を数値比較する時、文字列を 0 に変換する」という挙動だったため。

```php
// PHP 7 の挙動
var_dump("abc" == 0); // true (!)
```

この挙動はバグの温床だったため、PHP 8 で変更された。
現在は、数値文字列でない文字列と数値の比較は **文字列同士として比較される**。

```php
// PHP 8 の挙動
var_dump("abc" == 0);   // false
var_dump("abc" == "0"); // false
```

## Java との対比

| 言語 | 等価比較 | 同一性比較 |
|------|----------|------------|
| Java | `.equals()` (値) | `==` (参照) |
| PHP | `==` (型変換あり) | `===` (型変換なし) |

Java では `==` が参照比較で、`.equals()` が値比較だった。
PHP の `==` は Java とは全く別物で、「型変換してから値を比較する」という独自の動きをする。

業務で PHP を書くときは、**原則 `===` を使う** と覚えてしまってよい。
`==` を使う場面は「型が違ってもいいから値だけ見たい」という意図が明確なときだけに限定する。

## つまずきやすい点

### 1. フォーム入力の比較

`$_POST` や `$_GET` で受け取った値は **常に文字列**。
これを整数と比較するときに型を意識しないとバグる。

```php
// $_POST['age'] は文字列 "20"
if ($_POST['age'] === 20) {
    // ここに来ない! 型が違う
}

if ((int)$_POST['age'] === 20) {
    // OK: 明示的にキャストする
}
```

Laravel ではバリデーションやキャストの仕組みでこれを隠蔽しているが、生のPHPを書くときは意識が必要。

### 2. データベースから取得した値

DB から取得した値も、設定によっては数値カラムが文字列で返ってくることがある。
`===` を使うことで、こうした型の不一致を早期に検知できる。

### 3. `in_array` の罠

`in_array` の第3引数を `true` にしないと、内部で `==` 比較になる。

```php
in_array("abc", [0, 1, 2]);       // 結果は環境依存(PHP 7 と 8 で違う)
in_array("abc", [0, 1, 2], true); // 厳密比較。安全。
```

## 別の書き方

PHP 8 では `match` 式も厳密比較(`===`)を使う。
`switch` 文は緩い比較(`==`)なので、新規コードでは `match` を使うのが安全。

```php
// switch: 緩い比較
switch ($value) {
    case 0:
        // "abc" や null も来てしまう可能性
}

// match: 厳密比較
match ($value) {
    0 => '...',  // 0 だけがマッチ
};
```
