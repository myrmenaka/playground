# S3: `declare(strict_types=1)` で型チェックの挙動を比較する

## 目的

PHP の型チェックには「強制モード」と「厳密モード」の2つがあることを、実際に動かして体感する。
`declare(strict_types=1);` を書くことで、PHP がどう振る舞いを変えるかを目で見て理解する。

## ファイル名

`my_answers/s03a_no_strict.php`
`my_answers/s03b_with_strict.php`

## 取り組み方

このStepは **写経 → 動作比較 → ノート整理** 方式です。

1. 2つのファイルを `my_answers/` に写経する
   - `s03a_no_strict.php` (strict_types **なし**)
   - `s03b_with_strict.php` (strict_types **あり**)
2. それぞれを実行して、出力(またはエラー)の違いを観察する
3. 違いを自分の言葉でノートアプリに整理する

## 比較する関数

両方のファイルで、同じ関数を定義する:

```php
function add(int $a, int $b): int
{
    return $a + $b;
}
```

これに対して、以下を順に呼び出す:

1. `add(1, 2)` — 正常系
2. `add("3", "4")` — 文字列だが数値として解釈できる
3. `add("abc", "def")` — 数値として解釈できない文字列

## 観察するポイント

- strict_types **なし** のとき、どこまで通る? どこでエラーになる?
- strict_types **あり** のとき、どこでエラーになる?
- エラーメッセージの種類は?(`TypeError`? `Warning`? `Error`?)

## ノートに整理する内容

実行結果を観察してから、以下をノートアプリに書く:

1. 強制モード(デフォルト)と厳密モードの違いを一言で
2. 業務ではどちらを使うべきか、その理由
3. Laravel のソースコードを開いたら `declare(strict_types=1);` が書かれている確率はどれくらいか(予想でOK)

## ゴール

このStepが終わった時に、以下を口頭で説明できる:

- `declare(strict_types=1);` を書くと何が起きるか
- なぜモダンPHPの作法として「常に書く」が推奨されるのか
- ファイルのどこに書く必要があるか(位置の制約)
