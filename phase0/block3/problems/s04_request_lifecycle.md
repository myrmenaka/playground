# S4: PHP のリクエストモデルを理解する

## 目的

PHP の「リクエストごとプロセスモデル(Shared-Nothing アーキテクチャ)」を理解する。
Java のような常駐プロセス型の言語との違いを認識し、なぜ PHP にはセッションや DB が必須なのかを **必然性として** 理解する。

## なぜこれが重要か

Laravel に入ると、当たり前のように出てくる:

- セッション (`session()->put(...)`)
- キャッシュ (`Cache::remember(...)`)
- データベース永続化

これらが「なぜ必要なのか」を、PHP のリクエストモデルから理解しておくと、フレームワークの設計意図が見えてくる。

逆に言うと、PHP のリクエストモデルを知らないまま Laravel を学ぶと、**「とにかくそういうもの」として暗記する** ことになる。それは Phase の目的(評価できるエンジニアになる)から外れる。

## AI に投げる質問例

以下のような質問を順に投げてみる:

```
1. PHP の「リクエストごとプロセスモデル」とは何ですか?
   Java の常駐プロセス型と比較して、図解で説明してください。

2. なぜ PHP では、グローバル変数や静的変数が
   次のリクエストに引き継がれないのですか?

3. PHP がリクエストごとにプロセスを立ち上げて捨てるなら、
   なぜそれでも実用的な Web アプリケーションが作れるのですか?
   (= セッション、DB、キャッシュの役割)

4. Laravel は内部的にどうやって、リクエスト間で状態を保っていますか?
```

## ノートに整理する観点

ノートアプリに、以下の項目で整理する:

### 1. PHP のリクエストモデルとは

- リクエストが来るたびに何が起きるか
- リクエストが終わるとどうなるか
- 図(矢印と箱)を描いてもよい

### 2. Java との対比

- Java(Tomcat など)は何が違うか
- 常駐プロセス型 vs リクエスト型、それぞれのメリット・デメリット

### 3. なぜ状態を「外」に持つ必要があるか

- セッションは何のためにあるか
- DB は何のためにあるか(永続化以外の理由を含めて)
- キャッシュは何のためにあるか

### 4. このモデルを知っていると、Laravel で何が腑に落ちるか

- 自分の予想で書いてOK(Phase 1 に入って答え合わせする)

## ゴール

このStepが終わった時に、以下を口頭で説明できる:

- PHP の「リクエストごとプロセスモデル」を一言で
- なぜ PHP では静的変数がリクエスト間で共有されないか
- なぜセッションや DB が「必要」なのか(便利、ではなく必須である理由)
- Java(常駐型)との違いを1分で

## 補足: なぜ「コードを書かない Step」を入れているか

Phase 0 は「書く力をつける」が中心だが、Block 3 だけは PHP 独自の概念を整理する Step を意図的に入れている。

特にこの「リクエストモデル」は、Laravel の設計思想の根底にあるので、**Phase 1 に入る前に押さえておくと学習効率が大きく変わる**。

書く力は十分鍛えてきたので、ここで一度立ち止まって「PHP という言語そのもの」を理解する時間を取る。
