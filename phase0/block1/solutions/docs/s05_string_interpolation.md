# PHP-B1-S5: 解説

## 解答コード

```php
<?php

$name = "りんご";
$price = 150;

// パターン1: 連結演算子
echo "[1] 商品: " . $name . "、価格: " . $price . "円" . PHP_EOL;

// パターン2: ダブルクォート内の変数展開
echo "[2] 商品: {$name}、価格: {$price}円" . PHP_EOL;

// パターン3: sprintf
echo sprintf("[3] 商品: %s、価格: %d円", $name, $price) . PHP_EOL;
```

## 解説

### 3パターンの使い分け

PHP では同じ「文字列に変数を埋め込む」処理を、複数の方法で書ける。それぞれ向き不向きがある。

| パターン | コード例 | 向いている場面 |
|---------|---------|--------------|
| 1. 連結演算子 `.` | `"商品: " . $name . "円"` | 短い、変数が1〜2個の時 |
| 2. 変数展開 `{$var}` | `"商品: {$name}円"` | 短〜中程度、業務で最も多い |
| 3. `sprintf` | `sprintf("商品: %s円", $name)` | フォーマット指定が必要な時、ログ |

### パターン1: 連結演算子 `.`

```php
echo "[1] 商品: " . $name . "、価格: " . $price . "円" . PHP_EOL;
```

**メリット**:
- どこに変数が入るか視覚的に分かりやすい(初心者向け)
- 変数の型を気にせず連結できる(`int` も自動的に文字列化)

**デメリット**:
- 変数が増えると読みにくい
- `.` の前後にスペースを入れ忘れると `"a".$b."c"` のように密集してしまう

### パターン2: ダブルクォート内の変数展開

```php
echo "[2] 商品: {$name}、価格: {$price}円" . PHP_EOL;
```

**メリット**:
- **業務コードで最頻出**
- 短く、文章が自然に読める
- 配列やオブジェクトのプロパティも埋め込める(`{$user['name']}`、`{$user->name}`)

**デメリット**:
- シングルクォートと混在すると展開されない/されるの違いで混乱する
- 複雑なロジック(関数呼び出しなど)は埋め込めない(可能だが可読性が下がる)

### パターン3: `sprintf`

```php
echo sprintf("[3] 商品: %s、価格: %d円", $name, $price) . PHP_EOL;
```

**メリット**:
- **フォーマット指定**ができる(桁数、ゼロ埋め、小数点桁数など)
- C/Java の `String.format` と同じ感覚で使える
- ログメッセージなど **テンプレート + 値** の構造が明確になる場面で読みやすい

**デメリット**:
- 単純な埋め込みには冗長
- フォーマット指定子(`%s`、`%d` など)を覚える必要がある

### `sprintf` のフォーマット指定子

業務でよく使うものを抜粋:

| 指定子 | 意味 | 例 |
|--------|------|-----|
| `%s` | 文字列 | `sprintf("%s", "abc")` → `"abc"` |
| `%d` | 整数 | `sprintf("%d", 42)` → `"42"` |
| `%f` | 浮動小数点数 | `sprintf("%f", 3.14)` → `"3.140000"` |
| `%05d` | 5桁ゼロ埋め整数 | `sprintf("%05d", 42)` → `"00042"` |
| `%.2f` | 小数点以下2桁 | `sprintf("%.2f", 3.14159)` → `"3.14"` |
| `%%` | `%` 自体 | `sprintf("%d%%", 50)` → `"50%"` |

### `sprintf` と `printf` の違い

| 関数 | 戻り値 | 動作 |
|------|--------|------|
| `sprintf` | フォーマット結果の文字列 | 出力しない(変数に代入できる) |
| `printf` | 出力した文字数(int) | 直接出力する |

```php
// 戻り値を使いたい場合
$msg = sprintf("商品: %s", $name);
echo $msg;

// 直接出力したい場合
printf("商品: %s%s", $name, PHP_EOL);  // sprintf + echo の合成
```

## 実務でどれを使うか

業務コードを見ると、おおまかな使用頻度は:

```
変数展開 {$var}        ★★★★★(圧倒的に多い)
sprintf                ★★★☆☆(ログやフォーマット必要時)
連結演算子 .           ★★☆☆☆(短い場合のみ)
```

ただしチームのコーディング規約で揃えていることも多い。プロジェクトの既存コードに合わせるのが基本。

## Java との対比

| Java | PHP |
|------|-----|
| `"a" + b + "c"` | `"a" . $b . "c"`(パターン1) |
| `String.format("a%sc", b)` | `sprintf("a%sc", $b)`(パターン3) |
| (Java 13+ テキストブロック) | ヒアドキュメント(S4) |
| (Java 21+ String Templates ※プレビュー) | `"a{$b}c"`(パターン2) |

PHP のパターン2(変数展開)に相当する機能は、Java では長らくなかった。Java 21 で String Templates(プレビュー機能)として追加されつつあるが、まだ一般化していない。
**この「気軽な変数埋め込み」は PHP の利点の一つ**。

## つまずきやすいポイント

### 1. シングルクォートで変数展開を期待してしまう

```php
echo '商品: {$name}';
// → 商品: {$name}  ※そのまま出力
```

シングルクォートでは展開されないので、変数を埋め込みたい時は **必ずダブルクォート**。

### 2. `sprintf` のフォーマット指定子の数と引数の数を間違える

```php
sprintf("%s, %s", "Maru");
// → エラー: "Too few arguments to function sprintf()"
```

`%s` と `%d` の数 = 引数の数 になっているか確認する習慣をつけると良い。

### 3. `sprintf` の戻り値を `echo` し忘れる

```php
sprintf("商品: %s", $name);  // ← これだけだと何も出力されない
```

`sprintf` は **文字列を返すだけ** なので、`echo` や変数代入が必要。
直接出力したいなら `printf` を使う。

### 4. 連結時のスペース漏れ

```php
echo "商品: ".$name."、価格: ".$price;  // 動くが読みにくい
echo "商品: " . $name . "、価格: " . $price;  // 推奨
```

PSR-12 規約でも `.` の前後にスペースを入れることが推奨されている。

## 学習者の実装例

実際にこの問題を解いた際のコード例:

```php
<?php

$fruit = "りんご";
$price = 150;

echo "[1]商品:" . $fruit . "、価格:" . $price . "円" . PHP_EOL;
echo "[2]商品:{$fruit}、価格:{$price}円" . PHP_EOL;
echo sprintf("[3]商品:%s、価格:%d円", $fruit, $price) . PHP_EOL;
```

→ 3パターンとも正しく動作。`.` の前後のスペースも入っており、PSR-12 準拠。
変数名 `$fruit` は実装意図(りんご=果物)に沿っており、業務的にも自然。
