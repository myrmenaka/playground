# S14 解説: 偶数・奇数の判定

## ポイント

### `if` / `else` の基本構文

```php
if (条件式) {
    // 条件が true の時の処理
} else {
    // 条件が false の時の処理
}
```

Java と完全に同じ構文。条件式は `()` で囲み、ブロックは `{}` で囲む。

### 剰余演算子 `%`

```php
10 % 2  // 0(偶数)
11 % 2  // 1(奇数)
-7 % 2  // -1(負数の場合は符号が残る)
```

「2で割った余りが0なら偶数、そうでなければ奇数」が偶奇判定の定石。Java と同じ。

### `==` と `===` の違い

```php
0 == '0'    // true(型変換されて比較)
0 === '0'   // false(型も含めて比較)

0 == false  // true
0 === false // false

null == 0   // true(PHP 7まで)/ false(PHP 8以降)
null === 0  // false
```

| 演算子 | 名称 | 動作 |
|--------|------|------|
| `==` | 緩い等価 | 型変換してから比較 |
| `===` | 厳密等価 | 型と値の両方が一致する場合のみ true |

**現代のPHPでは原則 `===` を使う**。`==` は意図しない型変換でバグを生むため、PSR(PHP標準勧告)や主要な静的解析ツールも `===` を推奨している。

今回は `$num % 2` の結果は必ず `int` なので `== 0` でも動くが、`=== 0` のほうが意図が明確で安全。

## 別解

### 三項演算子(より短く書ける)

```php
$num = 11;
echo ($num % 2 === 0 ? '偶数' : '奇数') . PHP_EOL;
```

`条件 ? trueの場合 : falseの場合` の構文。Java と同じ。シンプルな分岐ならこちらのほうがすっきりする。

### `if` / `elseif` / `else`(3つ以上の分岐)

```php
if ($num > 0) {
    echo '正の数';
} elseif ($num < 0) {
    echo '負の数';
} else {
    echo 'ゼロ';
}
```

PHPでは `else if`(スペースあり)も `elseif`(スペースなし)も両方動くが、`elseif` のほうが一般的。

### 早期リターン(関数内で)

```php
function check(int $num): string {
    if ($num % 2 === 0) {
        return '偶数';
    }
    return '奇数';
}
```

`else` を書かずに `return` で早期に抜ける書き方。関数のネストが浅くなり読みやすい。後のStepで関数を扱う際に推奨される書き方。

## つまずきやすい点

### 1. 代入と比較の取り違え

```php
if ($num = 10) {       // ❌ 代入(常に10が返るので true 扱い)
if ($num == 10) {      // ⭕ 緩い比較
if ($num === 10) {     // ⭕ 厳密比較(推奨)
```

`=` 1つは代入、`==` 2つは緩い比較、`===` 3つは厳密比較。Java と同じ罠だが、PHPの動的型付けでは型エラーで気づけない場合がある分、より注意が必要。

### 2. 文字列の囲み方

```php
echo "偶数" . PHP_EOL;   // ⭕ 動く
echo '偶数' . PHP_EOL;   // ⭕ 動く(変数展開しないなら推奨)
```

PHPでは変数展開が不要な文字列はシングルクォート `'` で囲むのが慣習。微妙にパフォーマンスが良いという話もあるが、それより「変数展開していないことが一目で分かる」のが利点。今回は変数展開していないので `'偶数'` のほうがよりPHPらしい。

### 3. 0 の扱い

```php
if (0) { /* 実行されない */ }       // 0 は false 扱い
if (0 == false) { /* 実行される */ } // true
if (0 === false) { /* 実行されない */ } // 型が違うので false
```

PHPでは `0`、`'0'`、`null`、`''`、`[]` などが `false` 扱いされる(falsy値)。Java の `boolean` 厳密主義に慣れていると引っかかりやすい。

## Java との対比

```java
// Java
int num = 11;

if (num % 2 == 0) {
    System.out.println("偶数");
} else {
    System.out.println("奇数");
}
```

```php
// PHP
$num = 11;

if ($num % 2 === 0) {
    echo '偶数' . PHP_EOL;
} else {
    echo '奇数' . PHP_EOL;
}
```

| 観点 | Java | PHP |
|------|------|-----|
| `if` / `else` 構文 | 同じ | 同じ |
| 剰余演算子 | `%` | `%` |
| 等価比較 | `==`(プリミティブ)/ `equals()`(オブジェクト) | `==`(緩い)/ `===`(厳密) |
| 型の扱い | 静的型付け、型エラーで実行前に検出 | 動的型付け、`==` で意図しない変換が起きる |
| 推奨される比較 | `==`(プリミティブ) | `===` |

PHPの `if` 文自体はJavaとほぼ同じ感覚で書けるが、**比較演算子は `===` をデフォルトで使う**という習慣をここで身につけておくと、今後のLaravel開発でバグの温床を1つ減らせる。
