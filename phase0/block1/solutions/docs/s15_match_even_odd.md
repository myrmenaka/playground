# S15 解説: match 式で偶数・奇数の判定

## ポイント

### `match` 式の基本構文

```php
$result = match (式) {
    値1 => 返す値1,
    値2 => 返す値2,
    値3, 値4 => 返す値3,  // 複数の値を1つの分岐にまとめられる
    default => デフォルト値,
};
```

PHP 8.0 で導入された新しい構文。Java の switch 文の進化版と捉えると分かりやすい。

### `match` の特徴

| 特徴 | 説明 |
|------|------|
| **式である** | 値を返す。変数に代入したり、関数の引数に渡せる |
| **厳密比較** | `===` で比較される(switch の `==` とは違う) |
| **break 不要** | フォールスルー(次の case に流れる)がない |
| **網羅性チェック** | 一致する分岐がなく default もない場合は `UnhandledMatchError` を投げる |
| **コンパクト** | `=>` で1行に書けるので短い |

### switch との違い(PHPでも switch は使える)

```php
// switch 文(従来からある、文)
switch ($num % 2) {
    case 0:
        $result = '偶数';
        break;
    case 1:
        $result = '奇数';
        break;
}

// match 式(PHP 8〜、式)
$result = match ($num % 2) {
    0 => '偶数',
    1 => '奇数',
};
```

`match` のほうが圧倒的に短く、かつ安全。**PHP 8以降は match を優先**するのが現代的な書き方。

## 別解

### default 付き

```php
$num = 11;

$result = match ($num % 2) {
    0 => '偶数',
    default => '奇数',
};
```

`$num % 2` は必ず 0 か 1(正の数の場合)なので、`1 => '奇数'` の代わりに `default => '奇数'` でも動く。**負数の剰余を考慮するなら default のほうが安全**。

```php
-7 % 2  // -1 になる(0でも1でもない!)
```

このため、**実用上は default を入れた方が堅牢**。

### 複数値を1つの分岐に

```php
$score = 85;

$grade = match (true) {
    $score >= 90 => 'A',
    $score >= 80 => 'B',
    $score >= 70 => 'C',
    default => 'D',
};
```

`match (true)` のテクニック。各分岐の条件式が `true` と一致するかを評価するので、**範囲判定や複雑な条件分岐**に使える。Java の switch では絶対にできない芸当で、PHP 8 ならではの強力な書き方。

### 直接 echo に渡す

```php
echo match ($num % 2) {
    0 => '偶数',
    1 => '奇数',
} . PHP_EOL;
```

`match` は式なので、`echo` の引数に直接渡せる。中間変数 `$result` が不要なら、これでもOK。

## つまずきやすい点

### 1. セミコロンの位置

```php
$result = match ($num % 2) {
    0 => '偶数',
    1 => '奇数',
};   // ← ここに ; が必要(代入文だから)
```

`match` 全体が「式」なので、代入の終わりに `;` が必要。Java の switch 文は文なのでブロックの後に `;` は不要だが、PHPの `match` は式なので必要。慣れないとここで構文エラーが出やすい。

### 2. 各分岐の末尾はカンマ `,`

```php
$result = match ($num % 2) {
    0 => '偶数',   // カンマ
    1 => '奇数',   // 末尾もカンマOK(trailing comma)
};
```

switch の `;` ではなく `,`。配列リテラルと同じ感覚で書ける。

### 3. 厳密比較の罠

```php
$num = '0';   // 文字列の "0"

$result = match ($num) {
    0 => 'ゼロ',      // 一致しない('0' === 0 は false)
    '0' => 'ゼロ',    // こちらが一致
};
```

`match` は `===` で比較するので、型が違うと一致しない。switch の `==` と同じ感覚で書くと予想外の挙動になる。**ただしこれは罠というより安全装置**。型まで含めて意図通りの分岐ができる。

### 4. 一致する分岐がない場合

```php
$num = 5;

$result = match ($num) {
    0 => 'ゼロ',
    1 => 'いち',
};
// ❌ UnhandledMatchError(例外が投げられる)
```

`default` を書かないと例外になる。これは**バグの早期発見に繋がる安全機能**。switch のように静かに何もしないより、エラーで気付ける方が安全という設計思想。

## Java との対比

```java
// Java の switch 文(従来)
int num = 11;
String result;
switch (num % 2) {
    case 0:
        result = "偶数";
        break;
    case 1:
        result = "奇数";
        break;
    default:
        result = "不明";
}
System.out.println(result);

// Java 14+ の switch 式(matchに近い)
String result = switch (num % 2) {
    case 0 -> "偶数";
    case 1 -> "奇数";
    default -> "不明";
};
```

```php
// PHP 8 の match 式
$num = 11;
$result = match ($num % 2) {
    0 => '偶数',
    1 => '奇数',
};
echo $result . PHP_EOL;
```

| 観点 | Java switch文 | Java switch式(14+) | PHP match式(8+) |
|------|--------------|---------------------|-------------------|
| 値を返す | ✗ | ⭕ | ⭕ |
| 比較方法 | `==` (プリミティブ) | `==` | `===`(厳密) |
| break | 必要 | 不要(`->`) | 不要(`=>`) |
| 網羅性チェック | なし | あり | あり(例外) |
| 構文の区切り | `case x:` | `case x ->` | `x =>` |

**Java 14 の switch 式と PHP 8 の match 式は思想がそっくり**。背景としては、両言語とも「式として使える、安全で簡潔な分岐構文」を求めて進化した結果、似た形になった。Java Silver で switch 文に慣れている人は、`match` を「より安全な switch」と捉えれば違和感なく使える。

実務では Laravel のコントローラやサービスクラスで `match` が頻出する。ステータスコードの分岐、ロールごとの権限判定、種類ごとのフォーマット切り替えなど、**「何かを受け取って何かを返す」場面で `match` を使うとコードが劇的に綺麗になる**。
