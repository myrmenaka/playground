# インターフェースとは
クラスが実装すべきメソッドやプロパティを定義するための仕組みです。
インターフェイス自体には具体的な実装は含まれず、**「仕様と実装を分ける」**ことが主な目的です。これにより、コードの再利用性や保守性が向上します。

## 一言で言うと
クラスに規格書だけ渡して、ルールを守れば実装は自由な仕組み
使う側は規格書通りに呼び出せばいい

## なぜ必要か
中身を差し替えられることで、使う側は書き換える必要がなくなり、変更に強くなるため

## Javaのinterfaceとの違い・共通点

### 共通点
- 「契約を定義する」という思想は同じ
- `implements` で実装する
- 多重実装できる（`implements A, B, C`）
- インスタンス化できない
- 多重継承の代替手段として使う

### 違い
| 項目 | Java | PHP |
|---|---|---|
| デフォルトメソッド | あり（Java 8〜） | なし（traitで代用） |
| メソッドの可視性 | 暗黙的にpublic | publicを明示・publicのみ |
| 静的メソッドの実装 | 書ける | 書けない（宣言のみ） |
| 定数 | キーワード不要 | `const`必須 |

### 一番大事な違い
**PHPのインターフェースは実装を一切持てない。**
Javaのデフォルトメソッドに相当するものは、PHPでは `trait` で代用する。
