# S11 解説: インターフェースの本質と教える時のポイント

このStepは「自分の言葉でメモを書く」ことが目的のため、模範解答のメモは置かない。
ここでは指導側(メンター)が押さえておくべきポイントをまとめる。
学習者が「うまくメモが書けない」と感じた時の参照資料としても使える。

---

## 学習者がつまずきやすい3つの壁

### 壁1: 「なんでインターフェース挟むの?」

これは S11 段階では完全には分からなくて当然。
S12〜S14 で `Notifiable` を実装する中で「あ、こういうことか」と来る。

伝え方:
> 「今は『なんで?』のままでOKです。S14 で違うクラスが同じインターフェースを実装する体験をすると、価値が腹落ちします」

### 壁2: 「抽象クラスと何が違うの?」

S11 では深掘りしない。S15〜S17 で実装してから違いをまとめる構成になっている。
学習者が先に気になってしまったら「S17 でじっくりやるので、今は『どちらもメソッドを強制できる』くらいの理解でOK」と伝える。

### 壁3: 「Javaと何が違うのか整理できない」

Java Silver 保持者なら**ほぼ同じ**と伝えれば安心する。違いは以下:

| 観点 | Java | PHP |
|---|---|---|
| 宣言 | `interface Foo { ... }` | `interface Foo { ... }` |
| 実装 | `class Bar implements Foo` | `class Bar implements Foo` |
| 複数実装 | 可能 | 可能 |
| 定数 | 可能(暗黙的に `public static final`) | 可能(`const FOO = ...;`) |
| デフォルト実装 | 可能(`default` メソッド) | **不可** |
| メソッドの可視性 | 暗黙的に `public` | 明示的に `public`(`public function foo();`) |

## 「インターフェースとは何か」の3つの答え方

学習段階に応じて、メモの深さは変えてよい。

### レベル1(S11時点のゴール)

> 「クラスが守るべきメソッドの一覧。`implements` した側は、書かれているメソッドを必ず実装しないとエラーになる」

これが書ければOK。

### レベル2(S12〜S14 完了時のゴール)

> 「異なるクラスに『同じ振る舞いを持っている』ことを保証する仕組み。これによって、呼ぶ側は具体的なクラスを知らなくても、インターフェース型として扱える」

### レベル3(Phase 1 以降)

> 「実装を切り替え可能にする仕掛け。テスト時のモック差し替え、依存性逆転、Strategy パターンなどの基盤になる」

S11 では**レベル1で十分**。レベル2以降は後の Step で自然に到達する。

## メモが書けないと言われた時の声かけ

「自分の言葉で書く」が難しい学習者は多い。
その場合は以下の質問に答える形式に変えるとよい:

1. 「インターフェースを使うと、何が嬉しい?(1行)」
2. 「もしインターフェースが世の中に存在しなかったら、何が困る?(1行)」
3. 「Java の interface と比べて、PHP の interface はどこが同じでどこが違う?」
4. 「今、自分が一番モヤッとしているポイントを言葉にすると?」

この4問に答えるだけで、立派なメモになる。

## 次のStep(S12)への接続

S12 では `Notifiable` インターフェース(`notify(): string` メソッドのみ宣言)を写経する。
S11 で「メソッドの一覧を強制する仕組み」と理解できていれば、S12 の写経はスッと入ってくる。

逆に S12 で手を動かした後に S11 のメモを読み返すと、書いた当時より理解が深まっているはず。
**メモは一度書いて終わりではなく、S14 終了後に追記する想定**で書いておくとよい。
