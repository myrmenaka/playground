## ヒント

<details>
<summary>「一言で言うと」のヒント</summary>

S14 の解説で出てきた考え方が参考になります:

- インターフェース → 「**○○できる**」という能力を表す(例: `Notifiable` =「通知できる」)
- 抽象クラス → 「**○○の一種である**」という分類を表す(例: `AbstractAnimal` =「動物の一種」)

ただし、これはあくまで一つの捉え方。自分なりの言葉で書いてください。

</details>

<details>
<summary>「文法上の違い」のヒント</summary>

S14・S15・S16 の解説の最後に書いた比較表が、ほぼそのまま使えます。
ただし「写経して書く」のではなく、「**自分が書いた経験** を思い出しながら埋める」のがポイント。

- インターフェースで `private string $name;` と書いたらエラーが出る → プロパティ持てない
- 抽象クラスで `__construct` を書けた → コンストラクタ持てる
- ...といった具合に、自分の手の感覚から書く

</details>

<details>
<summary>「使い分け」のヒント</summary>

実務でよくある例:

- `Notifiable`(通知できる)、`Searchable`(検索できる)、`Cacheable`(キャッシュ可能)
 → これらは「能力」なので **インターフェース**
- `AbstractController`(コントローラの基底クラス)、`AbstractModel`(モデルの基底クラス)
 → これらは「種別の中で共通実装を持たせたい」ので **抽象クラス**

Laravel を書いていると `implements Authenticatable` のような書き方をよく見ます。これは「認証できる」という能力なのでインターフェース、というわけです。

</details>

## 確認ポイント

- インターフェースは「能力(can do)」、抽象クラスは「種別(is-a)」というニュアンスを掴めたか
- 文法上の違いを **自分の経験から** 書けたか(解説のコピペではなく)
- まだ曖昧な部分があったら、それを正直に書けたか(後で質問の起点になる)
